## 2. Existing architecture

Deterministic, no-LLM answer path: query → recall candidate from Walrus Memory
(`src/store.mjs`, MemWal SDK 0.1.13) → parse FR-v1 proof envelope (`src/schema.mjs`) → per-class
policy memory (`src/policy.mjs`) → freshness gate (`src/gate.mjs`: checkpoint window via Tatum Sui
Mainnet GraphQL ≤1 cached read + subject version/digest pin ≤1 read + wall-clock backstop; fail
closed) → FRESH answers, else WITHHELD. Corrections supersede via `supersedes` lineage.
`src/recall-checked.mjs` is the stable public contract (`recall_checked/v1`); CLI in
`src/recall-checked-cli.mjs`; static site generated by `scripts/proof-page.mjs`; static export by
`scripts/export-site.mjs`. Recorded evidence: 22 Mainnet memories + 306 checkpoint-stamped decisions
in `docs/evidence/proof-snapshot.json`.

## 5. Proposed (now chosen) identity

Naming audit: **Verity** (3,392 GitHub repos, npm taken), **Recheck** (753 repos, npm taken),
**StillTrue** (npm taken by an actively maintained same-space package, modified 2026-10-30;
stilltrue.xyz registered), **RecallGuard** (34 mostly-0★ GitHub repos, **npm `recallguard` 404**,
`recallguard.dev` NXDOMAIN, no trademark hits), **ChainRecall** (1 repo, npm 404, .dev free).

**Chosen: RecallGuard.** Pronounceable, spellable, product-relevant ("recall" + the gate that
guards it), free across npm/GitHub/domain, no conflicts. ChainRecall loses because it anchors the
brand to one chain rather than to the memory-verification category.

- Positioning: *RecallGuard is the freshness gate for AI-agent memory — it verifies a Walrus-backed
  memory against current Sui state through Tatum before your agent acts on it.*
- Tagline: *Your agent remembers. RecallGuard checks whether it's still true.*
- Voice: precise, evidence-first, plain-spoken; every claim labelled (recorded / offline replay /
  live / unverified); monospace for identifiers; no hype, no AI-marketing idiom.
- Visual: near-neutral dark canvas, one amber accent (#f4b860), flat surfaces, hairline borders,
  1px rules, generous whitespace, monospace for evidence. No gradients/glows/glass/neon.

Repo URL and package API/CLI contract are preserved (`recall_checked` bin and `recall_checked/v1`
schema stay); `recallguard` bin is added. Public repo name stays `freshness-bound-recall`.

## 6. MCP architecture

`@modelcontextprotocol/sdk` (official, v1.32.2, MIT, actively maintained — last publish 2026-10-23).
**stdio transport** first: no hosted infrastructure; installs from the existing package.
Implementation plan: `scripts/recallguard-mcp.mjs` entry, tools defined in `src/mcp/`:

| Tool | Kind | Purpose |
|---|---|---|
| `recall_checked` | read | Primary freshness-checked recall; returns `recall_checked/v1` structured output; recorded sample by default, live when `RECALLGUARD_LIVE=1` + credentials |
| `explain_decision` | read | Why accepted/withheld: verdict, signals, reason, lineage, prose explanation |
| `list_revisions` | read | Revision chain + supersedes relationships for a subject (snapshot-backed) |
| `get_evidence` | read | Provenance + verification evidence behind a decision/blob |
| `propose_correction` | read | Draft a correction; **never persists**; states the approval path |
| `store_correction` | write, **disabled by default** | Only when `RECALLGUARD_ENABLE_WRITES=true` **and** per-call `confirm: "STORE-CORRECTION"` **and** live mode; otherwise refuses before any runtime/client is created |

Security: read-only by default; argument validation via zod; query/limit bounds; 30 s timeout on
live calls; fail closed on missing verification; memory content treated as untrusted data (never
instructions, never raw `body` emitted — only parsed structured fields); provenance preserved in
every output; no secrets in output (values never read for display; booleans only); no wallet
requirement for the core flow; no arbitrary URL fetching; no LLM in the answer path.
Walrus/Taturn dependency unchanged — the MCP server enforces the same gate, it does not replace it.
Also exposes one resource (`recallguard://evidence/summary`) and one prompt
(`verify-before-answer`). Client configs: Claude Code, Codex, generic MCP — tested, not asserted.
